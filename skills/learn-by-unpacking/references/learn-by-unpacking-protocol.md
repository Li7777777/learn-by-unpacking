# 教程生成协议

本文是 `learn-by-unpacking` 的详细参考。它将用户提供的“图文并茂教程 + 伴读学习系统”提示词整理为可执行协议。

## 一、输入确认协议

在生成任何正文或文件之前，询问并确认：

1. 学习主题。
2. 阅读模式：主题讲解，或源码精读。
3. 源码精读时的项目路径/仓库地址和范围。默认范围为全部源码与关键配置，排除第三方依赖、构建产物、锁文件等生成物。
4. 每日可用时长，默认 150~180 分钟。
5. 目标学习天数。

先规划章节，再用以下公式计算建议：

```text
推荐天数 = ceil(全部章节总阅读时长 ÷ 学员每日可用时长)
```

单章通常估算 2000~7000 字、15~40 分钟。核心章节安排在前面，有依赖的章节连续安排；正文章节完成后追加全量复习日，该日不计入公式。

## 二、章节规划

每章必须有一个核心问题，并标注：

- 是什么、怎么做、为什么。
- 前置依赖。
- 难度：入门、核心、进阶。
- 核心度：★ 核心章节或普通章节。
- 预计阅读时长。
- 所属学习日。

每日内部顺序为：核心知识 -> 机制拆解 -> 进阶内容 -> 口述/画图/自测。

## 三、源码精读协议

建立覆盖清单：

| 文件 | 总行数 | 已读完 | 行号区间 -> 机制 | 定义/调用关系 |
|---|---:|---|---|---|
| `path/to/file` | 0 | 否/是 | `1-20` -> 入口初始化 | 被谁调用、调用谁 |

执行规则：

1. 先用目录工具盘点全部文件，并区分源码、配置、文档、测试、生成物和第三方依赖。
2. 范围内每个文件从第一行读到最后一行，分段读取时持续推进 offset，不能只读头部或抽样。
3. 每读完一个代码块，记录行号区间和一句话机制说明。
4. 读到函数、类、接口、枚举、常量和类型时，搜索定义点与调用点，并逐一读完。
5. 沿入口 -> 中间层 -> 底层追踪调用链；每个 import/export 符号都要映射到已阅读的文件。
6. 检查错误处理、边界条件、空值判断、默认值、阈值、配置、注释、测试和示例。
7. 在覆盖率 100% 前禁止写教程正文。
8. 行号只能来自真实读取结果。无法确认时写“待核实”。

开始写教程前，必须给出自证：

```text
源码文件总数：X
已完整读取：X
覆盖率：100%
关键行号索引：每个文件均已建立
```

## 四、教程文件规范

建议文件名：`README.md` 或 `教程-<主题>.md`。每章使用如下骨架：

```markdown
# 第N章：主标题 —— 一句吸引人的副标题

> 来源：（可选）
> 版本：（可选）
> 页面信息：XXXX字 · 含 XX 行代码 · 约 XX 分钟

> 开场导读：回顾上一章，点出本章要回答的 **核心问题**。

## 一、引子与直觉
### 1.1 小节

## 二、是什么
### 2.1 精确定义

## 三、怎么做
### 3.1 实现拆解

## 四、为什么这样设计
### 4.1 取舍与边界

## 五、总结：核心设计与可迁移方法

## 末节：下一站

> **本章关键源码索引**（源码模式）
> - `文件:行号` — 说明
```

每章至少选择四种手段：

1. ASCII 架构图、流程图或树形图。
2. SVG 图放在 `assets/`，正文引用后紧跟 `**配图说明**`。
3. 概念、方案或易混机制对比表。
4. 区分真实源码和示意伪代码的代码块。
5. blockquote 表达可追溯的关键洞察。
6. 加粗关键词和单独的“关键认知”句。

每个抽象概念尽量配生活类比；每个机制都解释为什么存在、换来了什么、牺牲了什么；章节结尾提炼 1~3 条可迁移方法。数字和事实必须可溯源。

## 五、伴读提示词规范

文件头部写明用途、复制范围、建议新开对话，以及教程和学习记录的相对路径。将实际提示词放在：

```text
--- 提示词开始 ---
...
--- 提示词结束 ---
```

提示词必须定义：

- 角色：资深伴读导师；风格是循循善诱、层层追问、一针见血。
- 材料：按天列出文件、章节、顺序、时长，核心章节标 ★，另列配图目录。
- 目标：使用“能复述、能画图、能对比、能推演”等可验证动词，覆盖 5~10 项。
- 阶段 A：导读 -> 独立阅读 -> 讲解 -> 追问，每章约 5 个来回。
- 阶段 B：半程时不看笔记画流程图或串讲主干，逐环节纠错。
- 阶段 C：概念 2、源码 2、设计 2、综合 1，共 7 题；必须先答题，再评分点评，最后给参考要点。
- 评分：每题 0~10；总分后给掌握画像，绿色 >=8、黄色 5~7、红色 <=3，并指出回看位置。
- 阶段 D：引导填写当天的学习记录。
- 复习日：薄弱点回看、错题重考（>=7 过关）、每章一题、全景图串讲、易混概念对答、结课清单。
- 行为：小步推进、先问后答、落到文件/行号/配图、串联前一天、要求复述或画图验证、默认全程中文。

题目库分四类，每道题都附考察要点供评分：概念题考定义/分类/边界，源码题考机制/参数/条件/行号，设计题考取舍/为什么/对比，综合题考完整链路或代码骨架。

## 六、学习记录规范

头部包括天数概览、伴读提示词路径、每日主题和总时长。每个 Day 区块包括：

1. 计划表：序、章节、文件、预计时长、完成。
2. 核心知识压缩笔记，用 `🔗` 连接前一天，`★` 标关键认知。
3. 成绩表：题号、主题、得分、点评、总分和掌握画像。
4. 疑问清单。
5. 错题复盘：题号、错因、正确思路。
6. 至少三条“机制 + 可迁移方法论”收获。
7. 串联图或口头串讲留白。

复习日包括复习目标、计划表、8~12 条“概念 = 一句话”的记忆锚点、重考成绩和结课确认清单。结课清单应逐章检查能否画图和复述，并让学员自评学习目标。

## 七、最终审查

交付前确认：主题/模式/天数已确认；公式和分配一致；教程每章有元信息、导读、四种图文手段、总结和下一站；三件套互相引用；事实、数字、命令、行号均可追溯；源码模式覆盖率为 100%。
